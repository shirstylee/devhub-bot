# Безопасность

Исправления безопасности предназначены для актуального состояния ветки `main`. Для старых коммитов и отдельных развёрнутых экземпляров поддержка не гарантируется.

## Сообщить об уязвимости

Если в [разделе Security репозитория](https://github.com/shirstylee/devhub-bot/security) доступна кнопка **Report a vulnerability**, используйте её для приватного сообщения.

Если приватные сообщения об уязвимостях ещё не включены, создайте Issue только с просьбой предоставить закрытый канал связи. Не включайте технические детали эксплуатации, токены, личные данные или пользовательские файлы в публичное обращение. Перед отправкой подробностей дождитесь согласованного закрытого канала.

В приватном сообщении укажите затронутый коммит, версии Python и зависимостей, ожидаемое и фактическое поведение, возможные последствия и минимальный обезличенный пример. Срок ответа заранее не гарантируется.

## Если утёк токен

1. Отзовите токен у @BotFather и выпустите новый.
2. Обновите локальный `.env` или переменную `BOT_TOKEN` на хостинге.
3. Проверьте файлы, всю историю Git, Issues, pull requests и логи запусков.
4. Если секрет был закоммичен, удалите его из истории по [инструкции GitHub](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository). Согласуйте переписывание истории с владельцами других копий.

Удаление секрета из последней версии файла или добавление `.env` в `.gitignore` не удаляет его из старых коммитов.

## Эксплуатация

Содержимое `bot/data`, `bot/temp` и `bot/cache` локальное и не предназначено для публикации. Данные могут включать Telegram user ID, file ID, текст водяного знака и загруженные файлы.

Постоянные настройки и история сохраняются только для действующих администраторов. Обычные пользовательские настройки находятся в ограниченном кэше памяти (512 записей на хранилище, срок действия 1 час бездействия; просроченные записи освобождаются при обращении), а их история не ведётся. FSM и агрегированная статистика также не сохраняются на диск. Это не исключает обработку Telegram ID, сообщений и временных файлов и не является гарантией отсутствия юридических обязанностей.

Язык обычного пользователя не записывается даже в кэш настроек: он определяется по `language_code` текущего Telegram-события. Для русского используется русский, для остальных кодов и при их отсутствии — английский. Сохранять ручной выбор языка могут только администраторы; неавторизованные нажатия старых кнопок выбора не создают языковую настройку.

Перед обновлением задайте основные Telegram user ID в `ADMIN_IDS`: при запуске бот удаляет старые записи неадминистраторов из настроек и истории, включая оставшиеся временные копии. При пустом `ADMIN_IDS` и отсутствии дополнительных администраторов удаляются все старые записи. Повреждённые файлы останавливают запуск. Отдельные резервные копии и внешние логи необходимо обслуживать самостоятельно.

`/admin` доступна только администраторам в личном чате. Неавторизованные команды и callback-запросы игнорируются без ответа, в том числе до выбора языка. Менять список дополнительных администраторов могут только основные из `ADMIN_IDS`; изменение их ID требует конфигурации и перезапуска на сервере. Не публикуйте список администраторов и их настройки.

Перед запуском для сторонних пользователей настройте ограничения памяти, CPU, диска и доступа к процессу. Проверка истории на секреты и запуск тестов не заменяют аудит безопасности всей обработки медиа.

Проверяйте актуальные предупреждения о зависимостях и обновляйте их с последующим запуском тестов. Не публикуйте настоящий `BOT_TOKEN` в примерах, workflow, логах и отчётах об ошибках.
