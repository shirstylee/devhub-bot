# 🧰 DevHub Bot

Многофункциональный Telegram-бот с инструментами для разработчиков, тестировщиков и дизайнеров. Интерфейс построен на inline-клавиатурах, Premium/Custom Emoji и отдельных графических панелях.

![DevHub Bot](Images/readme-cover.png)

## 🚀 Возможности

- форматирование и проверка JSON;
- генерация безопасных паролей;
- преобразование HEX/RGB и создание цветовых превью;
- конвертация PNG, JPG и WEBP, изменение размера и сжатие изображений;
- создание ZIP-архивов;
- генерация и распознавание QR-кодов;
- QR-коды для текста, ссылок, Wi-Fi, телефона и Telegram;
- генерация тестовых данных людей, компаний и платежных реквизитов;
- создание PNG-скриншотов кода в стиле Carbon;
- сокращение ссылок через `clck.ru`;
- преобразование PDF в изображения, сборка PDF и извлечение картинок;
- Base64 и URL encode/decode, SHA-256 и SHA-512;
- закрытая админ-панель: администраторы, общая статистика и управление сохранёнными настройками.
- защита от частых сообщений, повторных нажатий и перегрузки тяжёлыми запросами; администраторы обходят ограничения.

Модули перекрашивания и рендера оставлены в исходниках, но сейчас отключены в меню и маршрутах бота.

## 🌐 Интерфейс

- русский и английский языки;
- автоматический язык для обычных пользователей по интерфейсу Telegram, без отдельного сохранения: русский для `ru`, английский для остальных языков и при отсутствии кода;
- ручной выбор и сохранение языка только для администраторов через меню или `/language`;
- Premium Emoji из единого каталога;
- сохранение настроек на диске только для администраторов; у остальных — временно в памяти;
- редактирование существующей панели вместо цепочки сообщений.

## 🛠️ Стек

- Python `>=3.11,<3.15` (проверено на Python 3.14.7);
- aiogram 3, asyncio и FSM;
- Pillow, NumPy и OpenCV;
- PyMuPDF;
- PyAV и rlottie-python;
- Pygments, qrcode и fonttools;
- aiohttp и aiofiles.

Прямые зависимости закреплены в [`requirements.txt`](requirements.txt), а их транзитивные версии — в [`constraints.txt`](constraints.txt). Ограничения применяются автоматически при установке; переносите оба файла вместе.

## ⚡ Быстрый запуск

### Требования

- CPython `>=3.11,<3.15`;
- рекомендуемая и проверенная версия — Python `3.14.7`;
- Git для клонирования проекта;
- собственный токен Telegram-бота от [@BotFather](https://t.me/BotFather);
- доступ к интернету для Telegram API и внешних сервисов.

Минимальная версия обусловлена использованием `enum.StrEnum` и зависимостями NumPy и PyAV, которым требуется Python 3.11 или новее. Полный набор тестов проверен на Python 3.14.7; остальные версии диапазона отдельно не проверялись. Файл [`.python-version`](.python-version) задаёт рекомендуемую версию, а не минимальную.

### 1. 📥 Клонирование

```bash
git clone https://github.com/shirstylee/devhub-bot.git
cd devhub-bot
```

### 2. 🐍 Виртуальное окружение

Windows PowerShell:

```powershell
py -3.14 --version
py -3.14 -m venv .venv
.\.venv\Scripts\Activate.ps1
python --version
```

Если команда `py` недоступна, используйте полный путь к установленному Python. Например, для официального Python Install Manager:

```powershell
& "$env:LOCALAPPDATA\Python\bin\python3.14.exe" -m venv .venv
```

Linux/macOS:

```bash
python3.14 -m venv .venv
source .venv/bin/activate
python --version
```

Для рекомендуемой версии проверка должна вывести `Python 3.14.7`. Если используете другую версию из поддерживаемого диапазона, замените `3.14` в команде создания окружения.

### 3. 📦 Зависимости

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m pip check
```

Не копируйте локальную `.venv` на сервер: создайте окружение на самом сервере и установите зависимости заново. Успешный `pip check` проверяет совместимость пакетов, но не отсутствие уязвимостей и не совпадение с закреплёнными версиями.

### Проверка безопасности перед запуском на сервере

Установите также инструменты проверки и выполните аудит **в том окружении, из которого будет запущен бот**:

```bash
python -m pip install -r requirements.txt -r requirements-tools.txt
python -m pip check
python -m pip_audit --vulnerability-service osv --strict --progress-spinner off
```

Затем запустите тесты с фиктивным токеном, как описано в разделе «Тесты». Для запуска бота восстановите настоящие переменные окружения; не оставляйте `BOT_TOKEN=test-token`. При ошибке установки, тестов, недоступности базы аудита или найденных уязвимостях не переходите к запуску.

В обновлении безопасности от 1 ноября 2026 года проверены Pillow `13.0.0`, aiohttp `3.14.5`, Brotli `1.2.1`, certifi `2026.10.23`, multidict `6.9.1` и setuptools `84.1.0` (инструмент сборки/проверки). Строгий аудит полного тестового окружения не нашёл известных уязвимостей на дату проверки. Это не гарантия отсутствия неизвестных или будущих уязвимостей.

GitHub Actions запускает тесты и аудит на Linux с Python 3.11 и 3.14 при push в `main`, pull request и ручном запуске. Workflow использует только фиктивный токен и не запускает polling. Новые тесты дополнительно проверяют соответствие установленных версий `requirements.txt` и `constraints.txt`, чтобы устаревшая `.venv` не прошла незамеченной.

### 4. 🔑 Токен Telegram-бота

Создайте своего бота через [@BotFather](https://t.me/BotFather), затем скопируйте файл `.env.example` в `.env`.

Windows PowerShell:

```powershell
Copy-Item .env.example .env
```

Linux/macOS:

```bash
cp .env.example .env
```

Замените значение в `.env` настоящим токеном своего бота:

```dotenv
BOT_TOKEN=your_bot_token
ADMIN_IDS=
```

`BOT_TOKEN` — единственная обязательная переменная окружения. Её также можно задать средствами хостинга без файла `.env`. Файл `.env` исключён из Git и не должен публиковаться.

`ADMIN_IDS` — необязательный список числовых Telegram user ID основных администраторов через запятую. Укажите собственные ID на сервере, затем перезапустите бот. Не используйте @username, ID бота или токен. При пустом значении основные администраторы не назначены; если дополнительные ещё не добавлялись, `/admin` недоступна всем. Неверный формат ID останавливает запуск, чтобы права не назначались случайно.

### 5. ▶️ Запуск

```bash
python main.py
```

Откройте своего бота в Telegram и отправьте `/start`. Бот получает обновления через long polling; публичный веб-сервер и webhook для этого запуска не нужны. Для одного токена запускайте один экземпляр polling-процесса.

## 🤖 Команды бота

- `/start` — запуск и главное меню;
- `/menu` — открыть главное меню;
- `/language` — изменить язык у администратора; обычному пользователю объясняет, что язык определяется настройками Telegram.
- `/admin` — закрытая админ-панель, только в личном чате для администраторов. Обычным пользователям команда ничего не отвечает.

## 🛡️ Админ-панель

- **Администраторы** — список ID и ролей. Основные администраторы из `ADMIN_IDS` могут добавлять и удалять дополнительных. Основные ID меняются только в конфигурации сервера. Удаление дополнительного администратора также очищает его сохранённые настройки и историю.
- **Статистика** — время работы, общие счётчики принятых сообщений, нажатий, ошибок обработчиков, кнопок инструментов и отклонённых защитой запросов. Без списка пользователей, имён, ID и текстов; счётчики сбрасываются при перезапуске.
- **Хранение данных** — описание политики и очистка старых записей неадминистраторов.
- **Сбросить мои настройки** — удалить собственные настройки, язык и историю после подтверждения.
- **Обновить / Главное меню** — обновить панель или перейти в обычное главное меню бота. Кнопки сброса настроек и обновления находятся в одном ряду. `/cancel` отменяет ввод ID при добавлении администратора.

Дополнительные администраторы имеют доступ к панели и сохранению своих настроек, но не могут менять список администраторов. Доступ проверяется для каждой команды и каждого нажатия; отозванные права действуют сразу.

## 🚦 Защита от спама

Защита включена автоматически. Основные и дополнительные администраторы обходят **все перечисленные ниже ограничения**, в том числе при занятом боте. Лимиты самого Telegram API и ресурсы сервера этим не отменяются.

- Сообщения и нажатия кнопок используют общий лимит одного пользователя, независимо от чата: запас 12 запросов, восстановление 1 запроса в секунду. Превышение даёт паузу 3 секунды; новые обращения во время паузы не продлевают её. Запас позволяет быстро пройти несколько меню без ожидания.
- Одновременно обрабатывается только один запрос обычного пользователя. Повторный запрос отклоняется, пока предыдущий не завершится; это также защищает состояния диалога от параллельных изменений.
- Общий лимит для обычных пользователей: запас 30 запросов, восстановление 10 запросов в секунду. Он помогает при обращениях с нескольких аккаунтов.
- Загрузка файлов, скриншоты кода, работа с изображениями, PDF, QR и сокращение ссылок занимают общий пул из 2 тяжёлых запросов обычных пользователей. Между запусками обработки одного пользователя — минимум 2 секунды. Простая загрузка файла занимает слот, но не мешает сразу выбрать действие над загруженным файлом.
- Файлы обычных пользователей размером более 20 МиБ отклоняются по метаданным Telegram **до скачивания**.
- Отклонённые запросы не ставятся в очередь и не выполняются позже: нужно повторить действие после паузы. Предупреждение отправляется не чаще раза в 10 секунд одному пользователю; остальные повторы игнорируются, включая повторные callback-запросы. Общее число предупреждений тоже ограничено, чтобы бот не отвечал спамом на спам.

Антиспам хранит только Telegram ID, счётчики и временные отметки **в памяти процесса**, без текстов, имён и записи на диск. Кэш ограничен 4096 пользователями. Неактивные записи истекают через 10 минут и очищаются при последующих запросах (проверка не чаще раза в 30 секунд); активная обработка не удаляется. При заполненном кэше новые обычные пользователи временно получают отказ, а существующие ограничения не сбрасываются. Перезапуск очищает весь кэш и счётчики.

Параметры находятся в `AntiSpamPolicy` в [`bot/services/anti_spam.py`](bot/services/anti_spam.py). Это защита одного polling-процесса от обычного флуда, а не гарантия защиты от DDoS или специально подготовленных вредоносных файлов. Изоляция обработки, контроль CPU, памяти и места на диске остаются задачей настройки сервера.

## 💾 Данные и внешние сервисы

На диске в `bot/data` сохраняются только ID дополнительных администраторов, настройки языка и инструментов администраторов, их параметры и история рендера. История отключённого модуля может содержать Telegram file ID и текст водяного знака. Язык обычного пользователя берётся из поля `language_code` текущего сообщения или нажатия в Telegram и отдельно не сохраняется ни в файле, ни в кэше настроек. Бот поддерживает русский и английский; для других языков и при отсутствии кода используется английский. При смене интерфейса Telegram бот использует новый переданный код со следующего обращения. Ручная настройка языка в меню доступна только администраторам; старые кнопки выбора не сохраняют язык обычного пользователя.

Остальные настройки обычных пользователей не записываются на диск: они действуют в памяти процесса, имеют срок действия 1 час бездействия и ограничены 512 пользователями на хранилище. Просроченные записи освобождаются при следующем обращении к хранилищу; весь кэш пропадает при остановке процесса. История для обычных пользователей не ведётся. Отдельно от этого кэша FSM-состояния диалогов и данные ввода находятся только в памяти и истекают через 15 минут бездействия.

### Автоочистка файлов и диалогов

- Исходники и результаты удаляются после завершения обработки и отправки, а частичные загрузки и неудачные результаты — при ошибке или отмене. Для загрузки, требующей следующего шага (например, выбора конвертации или сборки PDF), файл временно сохраняется до этого шага.
- Неиспользуемые файлы в `bot/temp` истекают через 10 минут. Фоновая уборка выполняется каждую минуту, поэтому физическое удаление может произойти в течение следующей минуты после истечения срока. При запуске удаляются также просроченные файлы предыдущего процесса по времени изменения на диске.
- Уборка обрабатывает только UUID-именованные файлы и каталоги, которые создаёт бот. Она не удаляет `.gitkeep`, посторонние файлы, `bot/data`, резервные копии, шрифты и файлы вне `bot/temp`; переходы по симлинкам и junction не разрешены.
- Текущие загрузки, обработка и отправка защищены от фоновой уборки. Если native-кодировщик продолжает работать в потоке после отмены ожидающей корутины, его файлы защищены до фактического завершения потока.
- Диалог и его данные ввода истекают через 15 минут бездействия: фоновой уборке не нужно новое сообщение пользователя. Активная обработка не прерывается, отсчёт бездействия возобновляется после её завершения. После истечения диалога откройте инструмент заново через `/menu`.
- При очистке/замене состояния удаляются связанные временные файлы. Пути уже удалённых файлов убираются из состояния без продления срока жизни диалога. При отказе файловой системы удаление повторяется; в журнал попадает только общее предупреждение без ID, путей и содержимого.
- Эти правила применяются **ко всем, включая администраторов**. Они не меняют обход антиспама и не удаляют сохранённые на диске настройки, язык или историю администраторов. Кэш обычных настроек с часовым сроком также не является хранилищем данных ввода и этим обновлением не изменён.

Параметры заданы в `TEMP_FILE_TTL` (10 минут), `DIALOG_TTL` (15 минут) и `CLEANUP_INTERVAL` (1 минута). Это техническая минимизация хранения, а не обещание удаления сообщений из Telegram или юридического освобождения от требований по персональным данным.

**При первом запуске после обновления** бот автоматически удалит из трёх файлов настроек/истории записи всех, кто не входит в действующий список администраторов, включая старые временные копии этих файлов. Перед запуском обязательно задайте `ADMIN_IDS` на сервере, если хотите сохранить настройки основных администраторов. При пустом списке и отсутствии дополнительных администраторов будут удалены все старые записи. Повреждённый файл останавливает запуск: его нужно проверить локально, а не публиковать в Issue. Очистка не затрагивает отдельные резервные копии, логи или данные Telegram.

Временные пользовательские файлы находятся в `bot/temp`, а загруженные шрифты — в `bot/cache/fonts`. Эти папки исключены из Git; в `data` и `temp` отслеживаются только `.gitkeep`. Файлы для обработки временно скачиваются на диск, а сообщения и Telegram ID обрабатываются в памяти. Отсутствие постоянных настроек обычных пользователей не означает отсутствия обработки персональных данных; эта настройка сама по себе не гарантирует освобождения от юридических обязанностей.

Бот использует Telegram API. При сокращении ссылки её адрес передаётся `clck.ru`. При загрузке Google Font название шрифта и текст водяного знака передаются Google Fonts для подбора нужных символов. Это стоит учитывать при работе с конфиденциальными данными.

## 🔒 Безопасность и участие

- храните токен только в локальном `.env` или переменных окружения;
- не прикладывайте пользовательские файлы, базы, логи и секреты к Issues или pull requests;
- перед коммитом проверяйте `git status` и `git diff --cached`;
